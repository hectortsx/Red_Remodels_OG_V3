## Data flow

1. A visitor requests a page and assets through CloudFront and the private S3 site origin. Maintained production pages request Google Analytics only after a valid visitor acceptance. Their fonts are now served locally; the October 28 scoped release removed Google Fonts links.
2. Focusing a maintained form preloads Cloudflare’s Turnstile SDK. Submission runs a challenge with the public sitekey and action `contact`; no contact fields are passed to the SDK by the application.
3. The browser sends contact fields and a Turnstile token as JSON to same-origin `/api/contact`. CloudFront forwards the request to API Gateway and Lambda using the private origin header.
4. Lambda validates fields and abuse controls, then sends only the private widget secret and token to Cloudflare Siteverify. It checks success, approved hostname, and action before email delivery. It does not supply the optional visitor `remoteip` parameter. This does not prevent Cloudflare from observing the browser’s IP during SDK requests.
5. SES delivers the business notification to the configured primary and CC inboxes. The handler also attempts a confirmation to the submitter when enabled. Mailboxes, forwarding destinations, downloaded copies, and backups create separate retention/deletion surfaces.
6. Operational logs and aggregate alarms support troubleshooting. Provider and mailbox processing/storage locations require separate account/contract review; AWS `us-east-1` does not establish that every vendor processes data only in that region.

## Cookies and browser storage

The [cookie inventory](./COOKIE_INVENTORY.md) records the previously observed `_ga` and `_ga_SP8EDYP71R` analytics cookies and the October 28 live request check. Before preference deployment GA4 sent a page view before form interaction. The deployed [Accept/Reject controls](./COOKIE_PREFERENCES.md) now block analytics until acceptance; empty-field focus still loads the Cloudflare SDK independently. The preference localStorage key stores only version, choice and choice time, valid for 180 days, and is not transmitted to the server. The present browser API cannot read cookie/storage metadata, so a fresh-profile cookie enumeration and exact lifetimes remain open. No cookie or analytics identifier values were recorded.

This does not rule out GA4 automatic/enhanced events or account-side settings. Shared Accept/Reject controls are now deployed and live request gating is verified. A complete clean-profile cookie/storage metadata inventory remains open.
